# API Key 列表周期用量

`GET /admin/api-keys` 保持原有筛选、分页与累计字段，并在配置了周期限额的条目中提供：

- `rate_limit_usage`：当前固定窗口的用量、各维度配额和 `starts_at` / `resets_at`，结构与密钥详情用量接口一致。
- `rate_limit_usage_unavailable: true`：窗口用量读取失败。此时不返回伪造的零用量，密钥列表仍然可用。

数据直接读取 usage manager 的内存计数，不查询请求日志、不增加逐个密钥的 HTTP 请求。窗口顺序为 `1h`、`5h`、`1d`、`7d`、`30d`，仅包含密钥配置的窗口。没有周期限制时上述字段可省略。旧版本响应缺少这些字段时，前端保留已配置限额，用量显示未知。

Website 以累计加已配置周期的紧凑行展示花费、请求数和 Token。金额单位为 Credits，接口金额仍为 micro-CNY。请求数及 Token 的排序保持按累计值。窗口过期且新数据尚未到达时，不继续展示上一窗口的用量或限流状态；倒计时来自 `resets_at`，用量每 30 秒刷新。

5h/7d 为每个 Key 首次使用起算的独立窗口（分别为 5 小时、168 小时）。`state` 为 `idle` / `active` / `expired`；idle/expired 用量为 0，页面显示“待使用”，hover 区分首次/下次使用后开始，活动窗口 hover 展示准确起止时间。读取列表和详情不会开窗。其他周期继续采用原固定窗口规则。
